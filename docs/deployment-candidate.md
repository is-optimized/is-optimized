## Topology and runtime contract

`infra/Pulumi.yaml` creates one zonal e2-micro in us-central1-a, one 10GB pd-standard boot disk, one regional static IPv4, a dedicated VPC/subnet, Cloudflare-only TCP80/443 ingress, a runtime service account, a Firestore default database/index, and private report/image/TLS-cache buckets. There is no NAT, load balancer, forwarding rule, instance template or managed instance group. The static address remains stable across VM replacement. A single zonal VM has no failover or autoscaling; replacement can interrupt service.

The application handles origin TLS. Metadata enables HTTPS, disables SMS, names the report/TLS buckets, pins the public host allowlist to is-optimized.com and www.is-optimized.com, and supplies the ACME email/directory. It also sets trusted proxy CIDRs to the same reviewed Cloudflare IPv4 list used by ingress. The VM has only external IPv4; Cloudflare still provides client IPv6 at its edge. Port8080 and SSH are not exposed. Serial output may be read for diagnostics; interactive serial access is disabled.

TLS cache stores certificate private keys and the ACME account key in its own GCS bucket, with uniform bucket access, public-access prevention, no expiry lifecycle, and bucket-scoped storage.objectUser for only the runtime identity. It is protected from deletion in Pulumi. Do not put certificate keys in metadata or image assets. GCS is encrypted at rest by default; this candidate does not create a billable customer KMS key. Report artifacts retain the existing30-day lifecycle. Firestore record/contact cleanup is a separate application gate; keep SMS and phone-data collection disabled.

Required runtime metadata keys coordinated with the HTTPS lane: `HTTPS_ENABLED`, `ACME_EMAIL`, `ACME_HOSTS`, `ACME_DIRECTORY_URL`, `GCS_TLS_BUCKET`, plus existing `PUBLIC_URL`, `GCP_PROJECT_ID`, `GCS_REPORT_BUCKET`, `SMS_ENABLED`, and `TRUSTED_PROXY_CIDRS`. Do not deploy this IaC with the earlier app binary: its metadata allowlist rejects the new keys. Rebuild the reviewed TLS integration image with ports80/443.

Raw disk/image/ELF hashes and source/toolchain pins belong in the release receipt. The pinned local-only `std:filesha256` v2.3.2 function computes the archive SHA-256 from `imageArchive` bytes at preview/apply time. GCS object names are `images/<SHA-256>/image.tar.gz`, and the image's `rawDisk.source` includes that object name. Any archive-byte change therefore changes the import URI and explicitly replaces the image; no manually maintained digest config is trusted. Reconcile cleanup into reviewed IaC using those exact retained IDs; do not assume `pulumi destroy` deletes retained images/objects. No generic age lifecycle is added to the image bucket.
